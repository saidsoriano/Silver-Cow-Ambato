🚗 1. El tablero — qué es Silver Cow

Silver Cow Ambato es un catálogo web de joyería de plata 925. Tú eres el conductor. La página es tu auto. Google Sheets es el motor. GitHub Pages es la carretera. OpenCode es tu copiloto.

📄 Misión Vender joyería de plata con estilo luxury. Clientes consultan el catálogo, arman pedido y lo envían por WhatsApp.
🛠 Stack HTML + CSS + JS vanilla · GitHub Pages · Google Sheets · Apps Script
📈 Productos 221 · 7 categorías · datos en vivo desde Sheets
🔒 Estado En producción

Las especificaciones completas del auto están en spec/constitution/.

💡 2. Encender el motor — abrir el proyecto

Para manejar Silver Cow, primero enciende el motor desde el lugar correcto:

cd ~/Documentos/Programacion/Paguina_joyas
opencode

Al abrir OpenCode desde esta carpeta, se cargan automáticamente:

  • Los 4 MCPs (Playwright, Firecrawl, GitHub, Sequential Thinking)
  • El skill de Omarchy (temas de escritorio Linux)
  • El AGENTS.md con las instrucciones del proyecto

Si abres OpenCode desde otra carpeta, estos no se cargan. Cada proyecto tiene su propia configuración.

🚙 3. El volante — actualizar productos

Los productos viven en Google Sheets. Tú los manejas desde allí, sin tocar código.

Columnas de la hoja

| nombre | precio | codigo | estado | esPedido | img | desc |
  • nombre — nombre corto del producto
  • precio — número (ej: 45.00)
  • codigo — código interno (ej: P-PL-296)
  • estado — disponible | pedido | agotado
  • esPedido — FALSE (stock directo) | TRUE (bajo pedido)
  • img — ruta de imagen (ej: pulseras/P-PL-296.jpg)
  • desc — descripción larga (opcional)

Subir cambios a la página

Después de editar Sheets, los cambios se ven en la página al instante. Si no se ven, incrementa el número en ?v=N en catalogo.js para forzar recarga.

// En catalogo.js, cambia este número cuando actualices productos:
const API_URL = '...&v=2';

⚡ 4. Acelerador — publicar cambios (git push)

Cada vez que cambies código (HTML, CSS, JS), debes pisar el acelerador para que se vea en internet:

git add .
git commit -m "Descripcion del cambio"
git push

GitHub Pages despliega automáticamente. Espera 1-2 minutos y los cambios estarán en:

https://saidsoriano.github.io/Silver-Cow-Ambato/

Reglas de oro

  • No hagas git push --force (pierdes historial)
  • Revisa los cambios antes de commitear
  • No subas tokens, claves ni datos sensibles

🔧 5. Mantenimiento — importar del proveedor

Cuando el proveedor (ItalSteel Odoo) agregue nuevos productos, usa el script de importación para traerlos:

.venv/bin/python extraer_proveedor.py pulseras
.venv/bin/python extraer_proveedor.py todas
  • El script scrapea el catálogo del proveedor
  • Genera un CSV listo para copiar a Google Sheets
  • Descarga las imágenes a las carpetas de cada categoría
  • Si una imagen ya existe, la salta (no descarga duplicados)

Este script solo corre en tu compu (está en .gitignore, no se sube a GitHub).

🗺 6. GPS — Spec-Driven Development

Silver Cow usa SDD (Spec-Driven Development) para planificar cada mejora. Piensa en esto como el GPS del proyecto: antes de manejar, defines la ruta.

¿Qué es SDD en simple?

Antes de pedirle a la IA que agregue algo nuevo, primero escribes qué quieres (spec), cómo hacerlo (plan) y qué pasos seguir (tasks). Luego el agente implementa. Así evitas pérdidas de tiempo y cambios de rumbo.

Estructura del GPS

spec/
├── constitution/ ← Documentos fijos del proyecto
│ ├── mission.md Identidad, audiencia, tono
│ ├── tech-stack.md Stack, MCPs, proveedores
│ └── roadmap.md Features actuales y planeadas
└── features/ ← Una carpeta por feature
└── NNN-nombre/
├── spec.md Qué hace y criterios de éxito
├── plan.md Cómo se implementa
└── tasks.md Checklist de tareas

Cómo agregar una feature nueva

  1. Actualiza el roadmap en spec/constitution/roadmap.md con la nueva feature
  2. Crea la carpeta spec/features/006-mi-feature/
  3. Escribe la spec (spec.md): historia de usuario + criterios de aceptación
  4. Escribe el plan (plan.md): archivos a tocar, enfoque técnico
  5. Crea las tareas (tasks.md): checklist verificable
  6. Implementa con la IA según lo que dice la spec
  7. Verifica contra los criterios de aceptación
  8. Registra en sesiones/sesion-NNN.md

Registrar sesiones

Cada vez que trabajes en el proyecto, crea una nota en sesiones/:

# Sesión 004 — 2026-07-12
## Resumen
[qué se hizo]
## Decisiones
| Decisión | Opción | Alternativa |
## Archivos tocados
## Pendientes

Features actuales documentadas

  • spec/features/001-catalogo-sheets/ — Catálogo desde Google Sheets
  • spec/features/002-diseno-luxury/ — Diseño gold accent
  • spec/features/003-carrito-whatsapp/ — Carrito + WhatsApp
  • spec/features/004-importador-proveedor/ — Scraper ItalSteel
  • spec/features/005-mcps-opencode/ — MCPs del proyecto

🙌 7. Caja de herramientas — MCPs

Los MCPs son como herramientas especializadas en tu maletero. Las usas cuando las necesitas:

📷 Playwright Saca fotos del auto (screenshots del catálogo en móvil y escritorio). Prueba que todo se vea bien sin abrir el navegador.
🔍 Firecrawl Busca repuestos (scrapea proveedores, encuentra información en la web).
🧠 Sequential Thinking Tu asistente de ruta: divide problemas complejos en pasos lógicos antes de actuar.
💾 GitHub El taller mecánico: issues, PRs, Actions, releases. Gestiona el repositorio sin salir de OpenCode.

Los MCPs se configuran en opencode.json. Si agregas uno nuevo, documéntalo allí.

⚠ 8. Luces testigo — solución de problemas

🚨 La página no muestra los productos nuevos

Incrementa ?v=N en catalogo.js (línea de la URL del script). Por ejemplo, de ?v=1 a ?v=2.

🚨 El deploy no se ve después de git push

Espera 1-2 minutos. Si sigue sin verse, revisa que el push fue exitoso y que estás en la rama main.

🚨 OpenCode no carga los MCPs

Asegúrate de abrir OpenCode dentro de la carpeta del proyecto (cd ~/Documentos/Programacion/Paguina_joyas). Revisa que opencode.json tenga los mcpServers.

🚨 Error al ejecutar extraer_proveedor.py

Verifica que el entorno virtual está activado o usa la ruta directa: .venv/bin/python extraer_proveedor.py. Si el proveedor cambió su sitio web, el script puede necesitar actualización.

🚨 Google Apps Script no responde

El script tiene un cold start: la primera petición después de inactividad tarda 5-10 segundos. Las siguientes son rápidas. Si deja de responder del todo, revisa el script en scripts/google_apps_script.js y vuelve a desplegarlo.
